# Source Capture SOP

## Purpose

Every important claim in `knowledge/` should trace back to a source record and a durable raw artifact. For web sources, save a cleaned Markdown extraction under `raw/<industry>/documents/` instead of relying only on a URL.

> [!important]
> This repository is read and managed in Obsidian. Keep synthesized notes Obsidian-friendly, and keep raw extracts traceable but separate from synthesis.

## Standard Workflow

1. Add the source to `knowledge/<industry>/sources.csv`.
2. Extract the source into `raw/<industry>/documents/`.
3. Keep the generated `source_capture_manifest.csv` with status, method, raw path, and errors.
4. Create or update the industry source-capture MOC note in `knowledge/<industry>/`.
5. Cite the `SRC-*` id in knowledge notes.
6. If extraction fails, keep the failed row in the manifest and write the next verification action in the source note or research TODO.

## Obsidian Conventions

- Knowledge notes live under `knowledge/<industry>/` and should use YAML properties: `title`, `date`, `tags`, and `aliases`.
- Use `[[wikilinks]]` for links between knowledge notes, such as `[[07-training-data]]` and `[[08-umi-gripper-research-and-business-plan]]`.
- Use Markdown relative links for raw artifacts outside the vault, for example `[SRC-robotics-060 raw extract](../../raw/robotics-embodied-ai/documents/SRC-robotics-060-mimicgen-a-data-generation-system-for-scalable-robot-learning-using-human-demons.md)`.
- Use callouts for status:
  - `> [!summary]` for source-set summaries.
  - `> [!warning]` for failed or fallback captures.
  - `> [!todo]` for sources needing browser/manual follow-up.
- Keep one MOC/index note per source set when the number of sources is large. Recommended filename: `00-source-capture-index.md`.
- Raw extracted files should include properties generated by the script: `source_id`, `title`, `source_type`, `publisher`, `source_date`, `url`, `evidence_grade`, `capture_method`, `captured_at`, `tags`, and `aliases`.

## Command

Use the project script:

```bash
uv run python tools/extract_sources_with_defuddle.py --industry robotics-embodied-ai
```

Extract a single source:

```bash
uv run python tools/extract_sources_with_defuddle.py --industry robotics-embodied-ai --source-id SRC-robotics-060
```

Extract already-recorded PDF sources into Markdown/JSON plus a key-information draft:

```bash
uv run python tools/extract_pdf_sources.py --industry robotics-embodied-ai
```

Extract a single PDF source:

```bash
uv run python tools/extract_pdf_sources.py --industry robotics-embodied-ai --source-id SRC-robotics-061
```

Run with an optional PDF backend. Prefer Docling for general research PDFs, or PyMuPDF for a lighter local setup:

```bash
uv run --with docling python tools/extract_pdf_sources.py --industry robotics-embodied-ai --source-id SRC-robotics-061
uv run --with pymupdf --with pymupdf4llm python tools/extract_pdf_sources.py --industry robotics-embodied-ai --source-id SRC-robotics-061
```

On macOS, the Docling backend is configured to use CPU in this project because the layout model can fail on Apple MPS for float64 tensors.

Overwrite existing extractions:

```bash
uv run python tools/extract_sources_with_defuddle.py --industry robotics-embodied-ai --force
```

Normalize existing raw Markdown files for Obsidian properties:

```bash
uv run python tools/normalize_raw_source_frontmatter.py --industry robotics-embodied-ai
```

Link `SRC-*` citations in knowledge notes to raw artifacts:

```bash
uv run python tools/link_source_refs.py --industry robotics-embodied-ai
```

## Method Rules

- Standard web pages: use `defuddle parse <url> --md`.
- Markdown URLs ending in `.md`, `.mdx`, or `.markdown`: download directly rather than running defuddle.
- PDF URLs: first preserve the PDF under `raw/<industry>/documents/`; then use `tools/extract_pdf_sources.py` to create `.md`, `.json`, and `.key-info.md` artifacts. The key-info file is an extraction draft and must be analyst-reviewed before claims move into `knowledge/`.
- JS-only pages or blocked sites: keep the defuddle failure reason, preserve raw HTML when possible, and use a secondary method later, such as official PDF, GitHub raw file, or manual browser capture.

## File Naming

Generated files use:

```text
raw/<industry>/documents/<SRC-ID>-<slugified-title>.md
raw/<industry>/documents/<SRC-ID>-<slugified-title>.pdf
raw/<industry>/documents/<SRC-ID>-<slugified-title>.json
raw/<industry>/documents/<SRC-ID>-<slugified-title>.key-info.md
raw/<industry>/documents/source_capture_manifest.csv
```

This makes any evidence id directly searchable with `rg` or file-name search.

## Research Discipline

- Do not put long source extracts into `knowledge/` notes.
- Do put source extracts and downloads under `raw/`.
- Keep `sources.csv` as the canonical source index.
- Keep extracted raw files as supporting evidence, not polished synthesis.
- In Obsidian, use knowledge notes for synthesis and raw files for evidence. A claim should be easy to trace from `[[industry note]]` -> `SRC-*` -> `sources.csv` -> raw extract.
- In knowledge notes, cite source ids as clickable links, for example [`SRC-robotics-060`](../raw/robotics-embodied-ai/documents/SRC-robotics-060-mimicgen-a-data-generation-system-for-scalable-robot-learning-using-human-demons.md). Use `tools/link_source_refs.py` after source capture to keep these links fresh.
