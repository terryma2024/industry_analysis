# 具身智能平台工程师 JD 快速入场扫描

## 研究问题

基于 [[career-direction-business-landing-knowhow-2026-06-09|具身智能业务落地 know-how 职业方向思考]]，本轮调研验证：

> 哪些具身智能 / 机器人岗位更可能让用户用已有软件平台经验较快进入行业，并在真实项目中积累行业理解？

已确认的第一筛选门槛：

> 优先选择把通用软件平台能力作为硬要求、把机器人领域知识作为可补齐能力的岗位。

## 第一轮结论

第一轮公开 JD 扫描支持这个筛选门槛。当前最值得优先看的岗位族群是：

1. 后端 / 云端 / Fleet / RobotOps 平台。
2. 数据管线 / 数据闭环 / 评测平台。
3. 仿真平台 / 仿真环境 / 测试验证平台。
4. 运营系统 / 工厂系统 / ERP-MRP / 内部效率系统。

当前不作为第一入口的岗位族群：

- 本体控制、运动控制、嵌入式实时系统。
- 强化学习、大模型训练、具身大脑核心算法。
- 纯数据运营或现场执行岗，除非它能明显转向平台系统建设。

## JD 快速筛选规则

### 正向信号

JD 中出现以下内容，说明更可能复用既有平台工程经验：

- 后端服务、API、微服务、分布式系统、高并发、数据库、Kubernetes。
- 云端平台、机器人云、Fleet Management、RobotOps、设备管理、遥测、日志、监控、告警。
- 数据管线、数据闭环、数据清洗、数据转换、特征提取、数据仓库、评测平台。
- 仿真平台、仿真环境、测试验证平台、MuJoCo、Isaac Sim、Gazebo。
- 运营系统、任务调度、内部工具、ERP、MRP、生产计划、交付效率系统。

### 反向信号

JD 第一屏如果把以下内容作为硬门槛，应降低优先级：

- 控制算法、运动规划、全身控制。
- 嵌入式、RTOS、驱动、实时控制。
- 强化学习、大模型训练、VLA/VLM 模型训练。
- 机械结构、电机、伺服、硬件设计。

## 公司与岗位信号

### 中国样本

- 宇树官网招聘页给出了较完整的公开岗位文本，是本轮中国样本中最可用的 JD 来源。
- 智元机器人官网有社会招聘入口，并展示了 Genie Studio、数据服务、开放平台等平台化方向，但飞书招聘页不易直接抓取具体 JD；下一轮可通过飞书、猎聘、Boss 直聘或内推渠道补齐具体岗位文本。
- 对中国市场，下一轮应重点扩展：智元、银河通用、优必选、傅利叶、逐际动力、乐聚、星海图、它石智航、自变量、极智嘉、快仓、优艾智合、海柔创新、仙工智能。

### 海外参照

1X 的公开岗位说明显示，具身智能公司确实存在一类非常贴合本次筛选门槛的岗位：

- 云端 / 基础设施 / fleet data。
- 仿真平台 / 仿真环境。
- 工厂运营系统 / ERP-MRP。
- 遥操作平台。

这些岗位不等于中国岗位机会，但可以作为判断中国 JD 是否“像一个好入口”的参照系。

## 初步判断

对用户当前阶段，最优先的岗位标题不一定叫“平台工程师”。更好的检索关键词组合是：

- 后端开发工程师 + 机器人 / 具身智能。
- 云平台工程师 / 机器人云平台 / 设备管理平台。
- 数据管线工程师 / 数据平台工程师 / 数据闭环工程师。
- 仿真平台工程师 / Simulation Platform Engineer。
- RobotOps / Fleet Management / 机器人运维平台。
- 运营系统 / 生产系统 / 内部效率平台。

最需要避免的误判是：看到“具身智能”或“机器人”就认为它是好入口。真正关键的是岗位的硬要求是否仍然是通用软件平台能力。

## 下一轮调研

下一轮建议建立 20-30 个中国岗位样本，字段包括：

- 公司、岗位、城市、来源、发布时间。
- 岗位族群：后端 / 云平台 / 数据闭环 / 仿真平台 / 运营系统 / 控制算法 / 大脑算法。
- 通用软件硬要求强度。
- 机器人领域硬要求强度。
- 是否接触真实客户 / 真实项目 / 真实机器人 fleet。
- 是否有加班、出差、现场交付、年龄与资历匹配风险。
