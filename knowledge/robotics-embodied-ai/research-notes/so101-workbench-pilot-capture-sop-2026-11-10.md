# SO-101工作台小样采集操作手册：手机与D435i

> [!summary] 本次只做这一件事
> 采下**同一布局、同一灯光下的一块工作台**，证明照片能重建、深度可回放、尺度可检查。先选约1m×1m的机器人安装区及周边可达区域，含桌边、底座、背景和固定基准；工作台更小时按实际尺寸。不要第一天就扫完整房间。

> [!important] 方案与实测分开
> 以下时长、距离、张数与阈值均为本项目起始操作值，不是设备规格保证。本文手册已编写，尚未连接或验收你的D435i。采集电脑默认优先用已有RealSense Viewer的Linux／Windows实体机；Mac仅查到枚举工具，不代表其Viewer和相机流已可用。不要为采集先改机器人ROS环境、刷新固件或重装显卡驱动。

## 0. 先看交付清单和顺序

准备→量尺寸→接D435i→30秒录制与回放→正式RGB-D扫台→手机拍照→独立检查照片→收尾核对→备份。首次操作预留半天，设备正常后采集本身可按约1–2小时安排，均为预算。

做完应得到：

- 一份设备／灯光／布局记录和测量表，所有未知留空并标待测。
- `00_smoke`约30秒测试录制，**已离开实时相机源并重新打开验证**。
- `01_static`约30秒固定机位数据、`02_sweep`约60–120秒连续扫台数据；必要补扫另建文件。
- 手机训练照片80–120张＋独立验证照片12–20张；实际head／wrist视角如可用各补数张，不要求为拍照执行机器人程序。
- 软件版本／流配置／深度与RGB截图、回放检查记录，以及完整原始录制文件。

本轮为总方案P0–P1的操作附件，不另作行业全链深研。场景重建和录制工具能力有官方依据；现场操作节奏与验收门槛是工程设计。

## 1. 开始前摆好现场

1. 准备手机、D435i、已知可传USB 3数据的线、电脑、卷尺、卡尺、秤、硬质标定板、纸胶带和记录纸。USB-C插头形状不代表线支持USB 3。先不用Hub和延长线，优先原装／已知良好数据线直连电脑。
2. 固定灯光，避免窗外日照快速改变；显示器关闭动态画面。清洁手机和相机镜片。
3. 操作者按真机正常停机流程使机器人保持稳定停放姿态，记录姿态照片。不拆底座，不松相机支架，不开启自动动作。杯子、工具等可动物体从静态背景移走，另拍单物体参考。
4. 桌面放至少3个**不共线**且可反复识别的固定基准A/B/C，最好再在竖直硬板上放D。用胶带固定，标记编号。不要把三点排成一条直线。手机和D435i都要看得到部分相同基准。
5. 定义A为本小样原点，A→B为+X，桌面内与其垂直方向为+Y，朝上为+Z。画一张俯视草图；基准点应选标记角点或中心之一，并全程一致。
6. 放两条尺度：一条沿桌面长边，一条沿另一方向或竖直方向；分别量长度。至少一条只做最终独立检查，不参与后续尺度拟合。
7. 标定板贴在硬板上，不手持入镜、不放在会晃的椅子上。打印用100%实际大小，量出真实格长。它可以保留在首轮技术小样中；若未来要去掉，另做有记录的无板采集，不能直接把有板和无板混成同一静态场景。

**现场禁变清单**：机器人位置、桌面物品、A/B/C/D、相机支架、窗帘和灯。手机和D435i可以移动，场景不动；人的影子尽量避开任务区。

## 2. 需要量什么：先填表，再拍摄

长度统一记mm；标明两个端点、量具、重复读数及是否用于拟合。每项量两次，差异明显则第三次复核；不要填想象的精度。桌边圆角、尺子零点和倾斜都要注意。

| 编号 | 必量项目 | 具体量法／用途 |
|---|---|---|
| M01 | 桌面长、宽、厚 | 边到边；厚度在可达位置用卡尺；建立桌子外形 |
| M02 | 桌高 | 地板到桌面上表面；前后或左右各一处，记录不平与倾斜 |
| M03 | A-B、A-C、B-C | 同一角点／中心到同一角点／中心；检验尺度和形状；不要只量一条边 |
| M04 | 独立检查长度H1、H2 | 不参与拟合；一横一纵／竖直，写清端点，拍近照 |
| M05 | 机器人底座定位 | 底座可识别安装点到桌面两条基准边的距离；底座朝向、底座底面相对桌面高度；勿靠目测写旋转角 |
| M06 | 安装孔或固定夹尺寸 | 可见孔中心间距、垫块厚度、夹具包络；不拆卸既有安装 |
| M07 | 相机支架 | 固定支架相对A及桌边的粗略位置、高度、朝向；只作标定初值，不当光心精确外参 |
| M08 | 任务物体 | 杯高、杯口内／外径、杯底外径、可测壁厚、质量；夹爪垫长宽厚、材质；无法测的写未知 |
| M09 | 标定板 | 实际格长、行列数、标记字典／文件名、板是否平整；手机拍板全貌 |
| M10 | 小样边界 | 哪块桌面、哪段背景／墙、桌下哪些区域；不可达或遮挡面单列 |

M08属于单物体建模资料，杯子不留在静态扫台中心；透明／反光杯不能要求D435i自动恢复毫米级杯壁。先完成M01–M05和M09–M10即可启动背景小样，其余缺项不伪造，动态任务区建模前补齐。

建议填写列：`id,端点说明,读数1_mm,读数2_mm,采用值_mm,量具,估计不确定度_mm,用途fit/check,参考照片,备注`。附带CSV模板见文末。

## 3. D435i怎么连接

### 3.1 插线与软件确认

1. 先将线接相机USB-C，再接电脑USB 3端口。相机放稳，线缆留松弛，移动范围不足时移动采集电脑，不拉扯相机／机器人。
2. 关闭占用这台相机的ROS节点、浏览器摄像头和其他采集程序；不需要同时运行ROS来录制Viewer数据。
3. 在**采集电脑自己的图形桌面**打开RealSense Viewer，Linux可在该桌面终端运行：

```bash
realsense-viewer
```

4. 界面应出现`D435I`／`D435i`设备。拍下设备名、序列号、固件、USB类型和Viewer版本（通常在About／设备信息）。序列号只保存在本地记录，公开报告可脱敏。
5. USB类型若显示2.x，先换已知良好线和主机端口，拔掉Hub，再重试；本小样以USB 3.x作为采集条件。不在2.x下硬套30fps配置。
6. Linux可选只读诊断：`rs-enumerate-devices -s`查看识别，完整`rs-enumerate-devices`查看设备／可用流；以本机`--help`为准。命令可识别相机，不代表Viewer图形与录制已合格。

没有Viewer时，先从[官方SDK入口](https://github.com/realsenseai/librealsense)选择对应操作系统的安装指引；这一步视具体电脑单独完成。别在未知系统上照抄跨发行版apt命令，也别把“已安装枚举工具”当成Viewer已安装。

### 3.2 首轮参数：保持简单

先停流再改分辨率／帧率。菜单命名随版本变，关键是下面各项实际生效并截图留档。[V]

| 项目 | 首轮选择 | 现场怎么判断 |
|---|---|---|
| Stereo Module | 开启Depth，原始格式Z16 | 2D中有随移动更新的深度画面 |
| Depth | 848×480、30fps，若实际提供此组合 | 本机列表不存在就记下可用组合；640×480、30fps可作测试回退，不冒充同规格 |
| RGB Camera | 开启Color，先640×480、30fps | 彩色画面持续更新；和Depth都开启，不只看3D点云 |
| IR左右图 | 首轮非必需 | 可为诊断额外开，避免一开始堆叠所有流 |
| IMU | 本轮可不启用 | 静态房间融合先依赖视觉位姿；IMU不是现成的房间绝对轨迹 |
| 深度预设 | Default起步，保存当前选项 | 改预设另建take；不混成一个参数不明的文件 |
| 深度曝光 | 先自动 | 固定场景看稳定性；若需改手动，先小样试验并记录数值 |
| RGB曝光／白平衡 | 稳定后能锁则锁 | 避免明显亮度／颜色跳变；锁后画面过暗就调整灯光或参数重录 |
| IR emitter | 默认启用（设备／菜单可用时） | 不最大化功率、不改硬件；记录实际开关状态 |
| 后处理 | 首轮关闭可关闭的孔洞填补、时域等增强，保存原始流 | 同时记录显示端处理开关；别把显示截图当原始深度 |

848×480是官方D435调参资料中的常用深度起点，不是对当前电脑的实测。[T] Depth与RGB同为30fps也不等于自动严格同步；最终要检查帧时间戳。记录SDK／固件／流配置，不为统一后缀盲目升级。

### 3.3 先看2D，再看3D

1. 相机先离桌面约0.6–1.0m、斜向下约30–45°，让桌面、桌边和标定基准都在画面内。这是试拍起点，可按实际视场和有效深度调整；不要贴着桌面扫。
2. 等约1–2分钟稳定，确认Depth与Color开关都为on，画面不是旧帧。
3. 对着哑光桌面或硬纸板，看深度是否大面积有效、稳定；不要首先用玻璃杯评价相机好坏。
4. 再切3D，若界面提供来源选项，选`Source=Depth`、`Texture=Color`。移动相机少许，点云应跟随变化。
5. 黑洞可能是无效深度，边缘颜色溢出可能是RGB与深度视点遮挡差异。回2D区分这两种情况，不用孔洞填充假装取得真实表面。[O]

## 4. D435i怎么录制与回放

### 4.1 先录30秒测试，确认格式

1. 保存目录选本地数据盘，先建本次唯一文件夹，例如`workbench_20261110_take01`，不要覆盖旧take。先为小样预留约10GB空闲作为保守操作预算；实际一分钟文件大小以测试录制测得，正式采集前按它估算并留余量。
2. Depth和Color同时开始播放，确认帧率稳定，再点设备标题栏的**Record／红色录制按钮**；旧版可能在设备旁菜单中叫`Record to File…`。[V][L]
3. 在保存对话框中沿用软件原生格式：旧版通常`.bag`；新构建可能`.db3`。**不要手工改扩展名当转换**。文件名用`00_smoke`加实际后缀。[L][N]
4. 确认红色录制指示与时间在变化。先固定10秒，慢速平移10秒，再停住10秒；让所有目标保持静止。
5. 点停止录制；若该版本以“所有流停止”结束录制，则停Depth与Color。等录制指示消失、文件写入完成后再关闭程序。需要继续采集时再开新文件。
6. 保存设备信息和流设置截图；文件应存在且非零，但这还不算通过。

### 4.2 真正回放一次

1. 停止实时流；通过`Add Source → Load Recorded Sequence`或同义的打开录制文件入口，选择刚才的`00_smoke`。
2. 确认当前是**录制源**（常见电影图标／文件名），不是仍在看USB实时源。必要时关闭实时设备源；测试录制已经结束后可断开相机，验证不依赖实时相机。
3. 同时显示Depth和Color；点Play，确认开头、中间、末尾内容符合刚才“固定→平移→固定”的动作，时长约30秒。
4. 试Pause／继续、拖进度条；选0.5倍速看中段，末尾能正常到达；某些格式／版本没有逐帧按钮不算失败。
5. 如果只有Color、深度全空、时长异常、末尾打不开或加载报错，先重做30秒测试，不开始正式扫台。
6. 在检查表记`录制格式、时长、RGB回放、Depth回放、开中尾检查、SDK版本、结果`。保留原录制，不只交截图／MP4／PLY。

`.bag`是Viewer的旧版SDK录制格式，`.db3`是新代码中的另一种存储路径；不要假定任意`ros2 bag play`都能读旧`.bag`，也不要假定所有SDK都能读新文件。**同一套采集SDK成功回放**是本轮首要门槛；若后续重建环境不同，再独立测试其读取能力。[L][N]

### 4.3 正式扫台：两段必录，一段按需

- **01_static，30秒**：固定相机，对着桌面和尺度基准。用于检查时间稳定性、深度缺失和桌面平面噪声。不要用相机外壳到桌面的卷尺距离直接当深度光心真值。
- **02_sweep，60–120秒**：起点停2秒→沿桌前左到右→绕可达侧面缓慢走弧线→回到起点，结尾停2秒。相机看向同一工作区，路径相邻画面持续重叠；建议起步约5–10cm/s，转动缓慢。始终尽量同时看到桌面、边缘和带纹理背景。此速度是操作建议，不是设备指标。
- **03_detail，按需30–60秒**：补底座旁和桌边遮挡，从另一高度或角度看。不可达背面写入未观测清单，不碰机器人来凑全覆盖。

每段录完立即回放开／中／尾，失败只重录该段；布局或参数改变则新take。不要边扫边举卷尺、移动基准或让人走进背景。录制本身没有计算房间相机轨迹，后续仍需RGB-D位姿估计与配准，不把一段bag称为已重建地图。

## 5. 手机怎么拍：停稳、绕行、分层

D435i扫完后移开相机和线缆，**不动任何场景基准和物体**。手机主摄1×，保持同一镜头和横屏方向；普通拍照模式，关闭人像、滤镜、美颜和会显著改变画面的模式。能锁曝光／白平衡／焦点则锁；不能锁的手机先试拍检查，不宣称已锁。保留原分辨率原文件，不经微信压缩、不裁剪、不抠图。拍摄重叠与多高度原则见总方案官方采集资料SRC-robotics-714。

| 组别 | 位置与镜头方向 | 起始数量预算 |
|---|---|---|
| A 中层弧线 | 镜头约高出桌面40–60cm，斜向下，沿可达外围每移动约10–15cm停稳拍一张 | 25–35张 |
| B 高层弧线 | 高出桌面约70–100cm，更明显俯视，补桌面与底座顶部 | 20–30张 |
| C 低层弧线 | 高出桌面约15–30cm，拍桌沿、底座侧面与背景，保留与A组的共同内容 | 20–30张 |
| D 细节及连接图 | 标记、桌边、安装位近照，并补近景与远景之间过渡图 | 15–25张 |

距离不合适时以“主体清晰、相邻照片60–80%重叠、不切换镜头”为准调整。总计约80–120张训练照片；只有前侧可达就拍弧线，并明确背面缺测。不要围着桌子连拍一百张几乎相同的正面照片。

具体每拍一张：站稳→检查整张无手指／遮挡→等待对焦完成→按快门→隔几张放大检查标记边缘与文字。相机尽量平移换视点，不仅原地转手机。机器人仍在画面时后续必须遮罩并单独建模；本轮不要求拆机器人，遮住的桌面背后如实标缺测。

**独立保留组**：完成A–D后，另拍12–20张新视点，放入`phone/holdout/`，不参与训练和尺度拟合；覆盖高／中／低视角及任务相机附近。记录“近似head／wrist视角”或“真实设备拍摄”，不要混淆。若真实相机已可用，保存各3–5张原图及其配置；wrist移动须走现有受控操作流程，未就绪就写未采，不为凑图临时执行动作。此次不完成完整手眼标定，不能以小样照片替代它。

## 6. 如何判断合格

### 6.1 收工前你就能检查的门槛A

全部勾选才标“采集初检通过”，不写“高保真重建通过”。

- [ ] 现场测量有单位、端点照片、两次读数；至少3个不共线共视基准与独立检查长度。
- [ ] D435i识别为目标设备，记录USB 3.x、软件／固件／实际流配置。
- [ ] 每个录制都能作为文件源重新打开，Depth和Color开头／中间／末尾都更新；无解码错误或明显长冻结。
- [ ] 静态哑光桌面中心区域大部分有深度，关键安装区没有持续大片空洞；手动观察的“大片”若有争议，先标待量化，不写百分比。
- [ ] 训练照片至少达到本轮80张起始预算，12–20张保留图独立存放；更少也可能可用，但先补足空间覆盖再送检。
- [ ] 随机放大20张和全部基准特写，标记／文字边缘清楚，无明显拖影；发现坏图就标记并补拍对应角度，不能只删图造成覆盖断裂。
- [ ] 手机和RGB-D之间场景未变，灯光基本一致；移动物体／人影／遮挡有记录。
- [ ] 原始文件已复制到第二位置，并核对文件数和大小；需要严格校验时计算SHA-256。原文件保留，备份读得到。

### 6.2 后处理才能确认的门槛B

这些需要解析录制与小样重建。现场未做就标“待处理”，不要靠Viewer截图填通过。下列数字是拟定小样门槛，可根据测量基线修订并留原因。

| 项目 | 起始检查方法／门槛 | 不合格怎么处理 |
|---|---|---|
| 帧完整性 | 各流时间戳单调；按实际帧率统计。目标丢帧≤1%，无>0.5秒空档；若计数／时钟不可得则未知 | 查USB／落盘速度／负载；降带宽后新take并重录 |
| 深度有效性 | 预先圈定哑光桌面ROI，排除反光与遮挡；统计Z16非零比例，目标≥90%；保留原始未填洞数据 | 调角度／光照／距离及曝光；仍差则实测平面建模，标RGB-D限制 |
| SfM相机解 | 训练照片注册率目标≥90%，任务区域无断开的相机组；注册率高也须看覆盖 | 补过渡视点与模糊缺口；不靠重复帧凑数量 |
| 小样尺度／几何 | 用拟合外的≥3条检查距离，覆盖两个方向与不同长度；误差目标≤max(10mm,真值的1%) | 查基准、变换、打印缩放、位姿与深度；和总方案整房20mm目标不是同口径 |
| 任务精度 | 桌高／底座关键几何仍以实测和精建为准，沿用总方案≤3mm目标 | 不因背景小样达到1%就宣称接触区达标 |
| 验证图 | 保留视点可渲染，标记／桌边／底座轮廓无系统性错位，遮挡顺序正确，失败图保存 | 分辨相机、几何与外观误差；小样尚不能给出通用PSNR门槛 |

≤0.7px内参RMS属于后续正式相机标定目标，本次“照片清楚”不代表已达到；手机和D435i的光心、畸变与位姿也不自动相同。

## 7. 常见问题：按症状处理

| 看到什么 | 先做什么 | 如何判定恢复 |
|---|---|---|
| 完全没有设备 | 换USB数据线／直连端口，关闭占用程序，查看枚举；权限错误单独处理 | 设备识别＋两路实时流＋录制回放都通过 |
| USB显示2.x／组合选不了 | 换已知USB 3线和端口，移除Hub；记录实际可用配置 | USB3及目标配置稳定，重新录测试段 |
| RGB在动，3D像旧画面 | 回2D检查Stereo Module和Depth是否on | Depth和Color同时更新，再看3D |
| 桌面大洞，杯子透明 | 改角度／距离，先看哑光参照；反光物体走实测建模 | 参照ROI质量改善；杯子仍可能需单独建模 |
| 桌边颜色贴错 | 比较原始深度与RGB，排查遮挡和外参／配准 | 不把贴图改善当无效深度恢复 |
| 文件存在但打不开／没深度 | 确认格式、SDK、录制开启流、停止收尾；重做30秒 | 同SDK文件源两路完整回放 |
| Linux Viewer报GLFW／GLX | 在实际图形桌面保留报错；查`nvidia-smi`与`cat /proc/driver/nvidia/version` | 普通Viewer实际启动并通过测试录制；不直接认定相机坏 |

历史上下文提示：旧会话曾在ai-station遇到GLX／显卡驱动不匹配，软件渲染只能作隔离试验，硬件路径当时未完成复验。这是2026-10-13记忆信息，**可能已过时，本轮未远程核验**；不能据此断言当前有同一问题，也不预先要求重启／改驱动。

## 8. 文件怎么交

下列目录是拟定布局；请建在有足够空间的本地数据盘。原始照片和录制不进本知识库Git，知识库只保存手册、模板与脱敏检查结论。

```text
workbench_20261110_take01/
  README.txt                 # 电脑/OS/手机/SDK/固件/布局/灯光/未观测区域
  measurements.csv           # 从模板复制填写，空值保持未知
  d435i/
    00_smoke.bag             # 或软件实际输出的.db3及所有伴随文件
    01_static.bag
    02_sweep.bag
    device-info.png
    stream-settings.png
    playback-check.txt
  phone/
    train/                   # 原图，不改像素；另存原名到新名映射如有改名
    holdout/                 # 不参与拟合
    measurement-reference/   # 尺子、端点、板规格照片，不混入训练
  actual-cameras/             # 未采就写README说明
  qc/                        # 初检表、坏图清单；后处理通过后再加报告
```

如果原生录制生成目录／metadata／多个数据文件，**整个目录一起保存**，不要只挑一个db3。记录每段文件名、时长、参数和回放结论；摆放或参数改动在新take中追溯。数据复制后再离场，原始采集保留到重建验收结束。
