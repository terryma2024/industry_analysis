# 机器人（具身智能） - 求职与学习视角

## 你的背景定位

你已有 20 年软件开发和互联网行业经验，并做过 300 人团队 Leader。这意味着你不需要把自己定位为“从零进入机器人行业的一线机械/控制工程师”。更合理的切入点是：

- 机器人软件平台负责人；
- 具身智能数据闭环/仿真训练平台负责人；
- 工业/仓储机器人解决方案产品负责人；
- 机器人云端运维、调度、Fleet Management、MLOps/RobotOps 负责人；
- 具身智能公司 CTO/工程 VP/产品技术负责人；
- 产业研究、投资分析或战略岗位。

## 不建议优先切入的岗位

- 纯机械结构设计：需要长期机械工程积累，不是你最高杠杆的位置。
- 底层控制算法从零做起：除非你愿意投入 1-2 年系统补课，否则性价比不高。
- 现场调试初级岗位：能学行业，但不匹配你的资历和组织能力。
- 只做概念 BD：如果不理解技术和交付，很容易被行业热度牵着走。

  - 能区分工业机器人、AMR、协作机器人、人形机器人、具身大模型；
  - 能说清为什么家庭服务不是短期最确定场景。

### 30-90 天：补软件到机器人的关键概念

| 主题 | 要学到什么程度 |
|---|---|
| ROS2/机器人软件架构 | 理解节点、话题、服务、动作、坐标系、仿真和部署，不必先成为底层专家。 |
| 运动控制基础 | 理解位置/速度/力控制、轨迹规划、PID、MPC、全身控制基本概念。 |
| 感知与传感 | 理解 RGBD、3D视觉、雷达、IMU、力传感、触觉传感的用途和限制。 |
| 仿真 | 理解 Isaac Sim、MuJoCo、Gazebo、sim-to-real 的价值和局限。 |
| 机器人数据闭环 | 理解遥操作、数据采集、标注、训练、评测、部署、回流。 |
| 工业场景 ROI | 理解客户为什么买机器人：节省人力、稳定质量、提升吞吐、降低危险。 |

### 90-180 天：做作品集

建议做 3 个项目，偏软件和产品化，不从机械硬件开始：

1. 机器人 Fleet Management 原型：
   - 多机器人状态监控、任务分配、异常告警、日志回放。
   - 展示你的分布式系统和平台能力。
2. 仿真数据闭环 Demo：
   - 用开源仿真环境模拟抓取/移动任务，记录数据、评测成功率。
   - 展示你理解 RobotOps/MLOps。
3. 工业场景 ROI 分析工具：
   - 输入工位、人力成本、机器人单价、维护成本、节拍，输出回本周期。
   - 展示你能连接技术、商业和投资判断。

### 180-365 天：进入行业

可选路径：

- 路径 A：加入具备真实客户的机器人公司，目标岗位是软件平台、数据平台、产品技术负责人。
- 路径 B：进入投资/产业研究方向，建立机器人公司跟踪体系和个人研究影响力。
- 路径 C：做独立顾问/行业产品负责人，帮助机器人公司补软件平台、交付体系和组织管理。

## 进入策略

| 方向 | 推荐度 | 原因 |
|---|---:|---|
| AMR/仓储/工业移动操作公司 | 高 | 软件、调度、平台、客户交付需求强，和你的背景匹配。 |
| 人形机器人创业公司 | 中高 | 弹性大，但需要识别是否只是 demo 驱动；适合工程管理/平台负责人。 |
| 上游零部件公司 | 中 | 更偏工业 B2B 和供应链，适合做产品、数字化、客户工程，不一定适合纯互联网背景。 |
| 大厂具身智能平台 | 中高 | 有算力、模型和生态，但组织复杂，岗位要求可能更偏 AI infra。 |
| 传统工业机器人公司 | 中 | 稳定、有客户，但文化和增长速度可能不如创业公司。 |

## 面试准备

- 准备一张你自己的“具身智能产业链图”。
- 准备一个“机器人软件平台架构图”。
- 准备 3 家目标公司的分析：产品、客户、收入、技术路线、组织短板。
- 能解释：
  - 为什么机器人难在真实世界；
  - 为什么数据闭环重要；
  - 为什么工业/仓储更可能先落地；
  - 软件团队如何和机械、控制、硬件、供应链协作。

## 职业判断

对你来说，最佳切入不是“我去补机械短板”，而是“我把软件平台、数据闭环、工程组织和商业化交付能力带进机器人行业”。具身智能公司未来会越来越像“硬件公司 + AI 公司 + 互联网平台 + 工业交付公司”的混合体，而你的优势正好在后半部分。
